# v264 — 답안 그림을 안 보내던 것 · 수식 속 % 가 그 줄을 먹던 것 · 빗금 분수

고친 파일: `practice.html` 한 개. 워커(`gichul-ai-worker`)·Supabase 는 안 건드림.

---

## 1. 뿌리 ① — 해설 만들기가 «문제 그림» 한 장만 보내고 있었음

### 무슨 일이었나

`ezMake()` — 카드의 **✎ 해설 만들기 · ↻ 다시 해석하기**, 그리고 자동 채우기 ·
일괄 채우기까지 전부 이 함수를 탐 — 안이 이랬음.

```js
const blob = r.q_url ? await fetch(r.q_url).then(x => x.blob()) : null;
const md0  = await askAI(easyPrompt(r, !blob), blob, 3600);
```

- `r.a_url` (답안 그림) 이 **한 번도 안 실림**.
- `askAI(prompt, blob, …)` 가 애초에 그림을 **한 장만** 받는 구조라, 위 줄만 고쳐서는
  두 장을 넣을 수가 없었음.
- 답이 그림으로만 있는 문항(= `a_md`·`a_text` 가 빈 문항)은 모델 쪽에 정답이 하나도
  안 감. 14-2 3번이 정확히 이 경우임.

거기에 프롬프트가 이랬음.

```
[답안 글(있으면 참고. 없으면 그림만 보고 판단)]
(없음)
```

그림에는 답이 없는데 «그림만 보고 판단» 하라고 시킨 꼴 → 지어내거나, 근거가 없어
칸을 못 채움.

### 어떻게 고쳤나

**① `askAI` — 그림 여러 장 (line 3465 부근)**
한 장을 주든 배열을 주든 받음. 기존 호출부(글자로 변환 · 막히는 곳 표시)는 그대로 돎.

**② `ezImg()` 새로 만듦 (`ezMake` 바로 위)**
- 그림 한 장 받아 오기. 못 받으면 `null`.
- 워커는 한 장이 4.6MB 를 넘으면 **말없이 빼고** 진행함 → 화면은 보냈다고 믿는데
  모델은 못 본 채 답함. 3.2MB 넘는 그림은 여기서 1600px · JPEG 로 줄여 보냄.
  **저장된 원본은 안 건드림.** 투명 PNG 는 흰 바탕을 깔고 구움(안 깔면 새까매짐).
  다 쓴 `objectURL` 은 반납함.

**③ `ezMake` — 두 장을 «문제 → 답안» 차례로**

```js
const qb = await ezImg(r.q_url);
const ab = await ezImg(r.a_url);
if(r.q_url && !qb && !(r.q_md || r.q_text))
  throw new Error("문제 그림을 받지 못했습니다 — 주소가 죽었는지 확인해 주세요");
const imgs = [qb, ab].filter(Boolean);
const md0 = await askAI(easyPrompt(r, !imgs.length, { q:!!qb, a:!!ab }), imgs, 3600);
```

- `throw` 줄이 중요함. `ezImg` 가 실패를 삼키게 만들어 놨더니, 문제 그림 주소가
  죽은 문항에서 **아무것도 안 보고 쓴 해설이 그럴듯하게 저장되는** 길이 새로 생겼음
  (예전 판은 `fetch` 가 터지면서 저절로 멈췄음). 그 멈춤을 되살림.

**④ `easyPrompt(r, textOnly, have)` — 어느 장이 무엇인지 못 박음**

```
그림 두 장을 붙였다. **첫째 장이 문제 그림, 둘째 장이 답안 그림(모범답안·해설)** 이다.
- 두 장을 반드시 다 읽어라. 둘째 장을 안 보고 쓴 해설은 틀린 해설이다.
- 도면이 있으면 기기 약호·정격·결선·번호표(A)(B)(C) 까지 그림에서 직접 읽어라.
- 최종값·단위·유효숫자·반올림은 둘째 장(답안)에 적힌 것을 그대로 따른다.
- 답안에 없는 값을 지어내지 마라. 확신이 안 서면 그 줄 앞에 «[확인필요] » 를 붙여라.
```

- 셋째 인자 `have` 는 **선택**. 안 넘기면 예전과 똑같이 굴어서, `easyPrompt` 를 감싸
  쓰는 v-설정 래퍼(`easyPrompt.__wrapped`, `arguments` 로 넘김)도 그대로 돎.
- «없으면 그림만 보고 판단» 문구는 **삭제**.

### 값 치르는 것

문항당 이미지 1장 → 2장. 입력 토큰 약 두 배. 자동·일괄 채우기도 같은 길을 탐.

## 2. 뿌리 ② — 수식 안의 `%` 가 그 줄을 통째로 먹고 있었음

### 무슨 일이었나

KaTeX 는 LaTeX 와 똑같이 `%` 를 **주석 시작**으로 읽음. 실제로 돌려서 확인한 결과:

| 넣은 것 | 화면 |
|---|---|
| `$%Z_{s}=315%$` | **(빈칸)** — 그려지긴 하는데 내용이 통째로 지워짐 |
| `$$I_s=\dfrac{100}{%Z}I_n=2777.06[A]$$` | **파싱 자체가 실패** → 날글자 `I_s=\dfrac{100}{%Z}…` 가 그대로 노출 |
| `$\%Z_{s}=315\%$` | `%Z_s = 315%` (정상) |

올린 화면에서 **「부호」 칸에 `%Z_{s}` 가 날글자로 보이고, 「답」이 `> %` 만 남은 것이
바로 이 두 번째 줄의 모양임.** 터지지도 빨개지지도 않고 소리 없이 사라져서, «모델이
이미지를 못 봤나» 로 보였던 것.

하필 이 과목은 `%Z` · `%R` · `%X` · 역률처럼 **`%` 가 답 그 자체**임.

### 어떻게 고쳤나

처음엔 `sciToTex()` (해설 전용 전처리) 에 넣었다가 **되돌리고**, 그리는 자리 한 곳으로
옮김. `sciToTex` 는 해설칸만 지나가서 문제·답안 칸의 `%Z` 는 그대로 당했기 때문.

`katex.min.js` 태그 바로 뒤(line 34~)에 `katex.render` · `katex.renderToString` 을
**그 덩어리 자리에서** 감쌈. auto-render 가 `katex.render` 를 부르므로
(0.16 `auto-render.js:188`), 이 한 곳이면 해설 · 문제 · 답안 · 주석 · 한눈에 ·
`ai-explain.js` 까지 전부 덮임.

```js
var pct = t => typeof t === "string" ? t.replace(/\\%|%/g, "\\%") : t;
```

- 이미 `\%` 로 온 것은 그대로 둠. 두 번 돌려도 같은 결과(`%%` 도 안전).
- 수식 **밖**의 `%` (줄글 «역률 80%») 는 katex 를 안 타므로 안 건드림.
- `katex` 가 실리기 «전에» 돌아야 해서, `Object.defineProperty` 로 실리는 순간을
  잡고 + 20초짜리 뒷문 폴러를 둠.
- **그릴 때** 고치는 것이라 이미 만들어 둔 해설 1330개가 **다시 안 돌려도** 제대로 나옴.

## 3. 뿌리 ③ — 분수가 `\dfrac` 으로 안 서고 빗금(`/`) 으로만 보이던 것

### 무슨 일이었나

두 갈래였음.

- **만드는 쪽** — `EASY_RULE` (✎ 해설 만들기 경로) 에 «분수를 어떻게 쓰라» 는 말이
  아예 없었음. 워커의 `SYS_SOL` (상세 Opus/Sonnet 경로) 에는 «분수는 `\dfrac{위}{아래}`.
  (1/58) 처럼 빗금으로 쓰지 않는다» 가 있었는데, 낱개 해설 쪽에만 그 줄이 빠져 있었음.
  그래서 모델이 `100/315` 처럼 빗금으로 써 보냄.
- **그리는 쪽** — `toTex()` 에 빗금을 분수로 세우는 길이 없음. 빗금이 오면 빗금 그대로 그림.

### 어떻게 고쳤나

**① 만드는 쪽 — `EASY_RULE` 에 한 줄 박음**

```
- ★ 분수는 반드시 \dfrac{위}{아래} 로 쓴다. (1/58) · P/(√3·V) 처럼 빗금으로 쓰지 마라.
  다만 단위 속 빗금([Wb/m²])과 변압비(22.9kV/3.3kV)는 빗금 그대로 둔다. 그건 나눗셈이 아니다.
```

**② 그리는 쪽 — %와 같은 자리(katex 래퍼)에서 빗금을 세움**

이미 만들어 둔 해설 1330개는 다시 안 돌려도 분수로 서야 하므로, 그리기 직전에 바꿈.

**함부로 세우면 안 되는 빗금이 있음.** 이 과목에서 `/` 는 나눗셈이 아닌 경우가 많음 —
단위(`Wb/m²`) · **변압비(`22.9kV/3.3kV`)** · 글월(`출력/입력`). 그래서 두 겹으로 막음.

- `\mathrm{}` · `\text{}` · `\mathbf{}` · `[대괄호]` 속은 통째로 빼 두고 건드리지 않음.
- 빗금 양옆이 **한 덩어리로 끝나는 것** 일 때만 세움. `22.9kV/3.3kV` 는 왼쪽이 `k` 에
  붙어 있어 «한 덩어리» 가 아니므로 안 건드림.

### 아는 한계

`50/60\,\mathrm{Hz}` 처럼 «50 또는 60Hz» 뜻으로 쓴 빗금은 분수로 서 버림.
수식 안에 그렇게 적는 일이 드물어 그냥 둠. 걸리면 그 칸만 `고쳐 쓰기` 로 손보면 됨.

### 돌려서 확인한 것

| 넣은 것 | 나온 것 | |
|---|---|---|
| `$R = 100/315$` | 100 위 / 315 아래로 **섬** | 세워야 할 것 |
| `$\rho = 1/58$` | 1 위 / 58 아래로 **섬** | 세워야 할 것 |
| `$TR\ 22.9kV/3.3kV$` | `22.9kV/3.3kV` **그대로** | ★ 건드리면 안 됨 |
| `$[\mathrm{Wb/m^2}]$` | `[Wb/m²]` **그대로** | ★ 건드리면 안 됨 |
| `$\text{출력/입력}$` | `출력/입력` **그대로** | ★ 건드리면 안 됨 |
| `$\dfrac{100}{15}\times 50$` | 그대로 정상 | 이미 분수 |

따로 16가지 무늬(첨자·근호·괄호식·단위 앞 분수 등)로도 두들겨서 **16/16 통과**함.
