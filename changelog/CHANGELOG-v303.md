## 원인 (이번 창: «회로·시퀀스인데 ans 가 빈 단계가 있다»)
- 진단상 Opus 는 이번엔 풀이를 배열 5~7단계로 제대로 보냈음
- v299 에서 회로형에 «모든 단계에 ans» 를 걸었는데, 해설 틀 설명은 «소문항을 끝내는 단계만 ans · 아니면 빈칸»
  → 규칙끼리 부딪혀, «동작 원리» 같은 설명 단계 하나 때문에 Opus 3번 + Sonnet 까지 부른 오탐

## 고침
- 검사 둘로
  - 필수(빠지면 다시 받기 · Sonnet 대체 · 확인 창): 풀이 없음 · 소문항 누락 · 소문항마다 «답 적은 단계» 없음 · 답 없음 · 자리표시
    · 부호가 글자/뜻 없음 · 계산형 식 네 줄 · 계산형 주어진 값·부호 · 회로형 단계 수
  - 보충(작은 틀로 한 번만 채워 보고, 확인 창 없이 저장 · 알림만): 먼저 알아야 할 것 · 검산 · 단계별 «왜»
    · 회로형 부호 개수 · 동작설명 줄 수 · 답 한 칸 몰아넣기
- ans 규칙: 모든 단계 → 소문항마다 ans 가 적힌 단계가 하나 이상 (단답·서술·나열·회로)
- 작은 틀로 받은 것을 합칠 때 «더 긴 쪽» → «바꿨을 때 검사가 나아지는 쪽» (같은 길이로 고쳐 온 것을 버리던 문제)
- 화면: 보충만 남으면 «ℹ 보충하면 좋은 곳 N» 알림 · 화면 쪽 검사도 같은 기준으로 완화

## 확인 (가짜 응답)
- 이번 캡처 모양(설명 단계 ans 빔): 호출 1번에 통과 (전에는 Opus 3 + Sonnet 1)
- 소문항 답 빠짐 → 작은 틀이 고친 것을 받아 Opus 로 통과 · 보충만 → 작은 틀 1번, 저장
- 앞선 시나리오(태그 누출 · 번호 열쇠 · 코드블록 · 임시본 · 잘림 · Sonnet 대체 · 전부 실패) 그대로 통과
