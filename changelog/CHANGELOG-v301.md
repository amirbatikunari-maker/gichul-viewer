# v301 — Opus 가 세 번 다 «풀이 0개» 로 오던 것: 읽는 법 넓힘 · 풀이만 받기 · Sonnet 대체 · 진단

고친 파일: `gichul-ai-worker/src/index.js`(워커 — 재배포, 빌드 v301) · `practice.html` · `sw.js` · `index.html`

## 뜬 창 («Opus 해설이 원칙에 못 미칩니다») 은?
- v297 의 보호 장치가 제대로 일한 것 — Opus 가 세 번 모두 풀이 단계 0개로 보내서, 있던 해설을 바꿀지 물은 것
- «취소» = 있던 해설 그대로

## 원인 후보 → 고침
- 워커는 steps 가 «배열» 이거나 «[ · { 로 시작하는 글자» 일 때만 읽었음. Opus 가
  {"(1)":{…},"(2)":{…}} 처럼 소문항 번호를 열쇠로 쓴 «객체» 나 ```json … ``` 로 감싼 글자로 보내면 전부 «0개»
  → 둘 다 읽음 (한 번에 통과 — 다시 받을 필요 없음)
- 그래도 풀이가 비면: 풀이·부호·주어진 값·검산만 채우는 «작은 틀(write_steps)» 로 한 번 더 받아 합침
- 그래도 Opus 가 원칙 미달이면: Sonnet 으로 한 번 받아 더 나으면 그것을 씀 → «⚠ Opus 가 틀을 못 지켜 Sonnet 으로 대신 뽑았습니다» · 저장된 만든 모델도 Sonnet
- 시간: 다시 받기 3분 30초 · 풀이만 5분 30초 · Sonnet 대체 6분 30초 안에서만 (화면은 10분 기다림)

## 진단
- 워커가 매 시도마다 «steps 가 어떤 모양으로 왔는지 · 멈춘 까닭» 을 diag 로 돌려줌
- 미달 확인 창 아래 [진단 — 받은 모양] 으로 보여 줌 → 또 나오면 그 줄을 보내 주면 원인이 바로 보임

## 확인 (가짜 응답)
- 번호 열쇠 객체 · 코드블록 글자 → 한 번에 steps 3개 · 계속 빈 것 → 풀이만 받기로 채움 · 끝까지 실패 → Sonnet 대체
- 예전 흐름(불량→불량→정상 · 임시본→이어서 완성본) 그대로 통과
