## 1. 「실기 변환」 탭이 처음 열면 텅 비던 것 — 치명

`ingest.html` 은 `practice.html?only=import` 를 창(iframe) 안에 끼워 넣는데,
그 창 안에서도 `simple.js` 가 돈다. 그런데 `simple.js` 는 «간단히» 모드에서
**`#boxFiles` · `#boxImport` 를 감추게** 돼 있다 — 그 창이 보여 주려는 바로 그 둘이다.

지금 화면이 멀쩡한 건 전에 「자세히」를 눌러 뒀기 때문(`app:simple = "0"`).
캐시를 지우거나 다른 기기에서 열면 **빈 화면**이 나온다.

`simple.js` 에 한 줄 넣어 그 창은 건드리지 않게 했다.

```js
if (location.search.includes("only=import")) return;
```

브라우저로 확인:

```
자동변환 탭 안 : boxFiles ✔ boxImport ✔ 훑어보기 ✔ 올리기 ✔ 빠진 문제만 ✔
실기뷰어 본화면 : boxFiles ✘ boxImport ✘   (원래대로 접힘)
```

## 2. 연도 목록이 가짜 회차로 뒤덮이던 것

책 한 권을 넣으면서 회차가 없는 덩어리에 가짜 연도를 붙였다 —
`9301` `9302` `9416`~`9425` `9523` `9001`~`9003`. 숫자로만 뜨니
무엇인지 알 수 없고 **개수만 스무 개 넘게** 늘어 보였다.

**데이터는 그대로 두고 보이는 이름만 바꿨다.**

| 저장된 값 | 화면에 뜨는 이름 |
|---|---|
| `9301` | 오고초려 |
| `9302` | 핵심빈출 |
| `9419` | 단답 · 2019년 |
| `9523` | 소방 · 2023년 |
| `9001` | 회차 미상 1 |

그리고 **「기출만」 단추**를 넣었다. **처음에는 실제 기출만 보인다.**

```
처음(기출만) : 2026년 · 2025년 · 2024년 · 2023년 · 2022년
단추         : 기출만 (16개 숨김)
```

한 번 더 누르면 전부 나온다. 전 회차 빈칸 모아보기·텍스트 뽑기에도 같은 이름표가 붙는다.

### 배점 100점 잣대도 같이 손봄

«배점 합이 100 이면 번호만 밀린 것» 이라는 판정은 **진짜 기출에만** 해당한다.
오고초려·핵심빈출·단답은 100점짜리가 아니라서 그대로 재면 늘 «미달» 로 나왔다.
가짜 회차에서는 그 판정을 아예 쓰지 않는다.

## 6. 실기 자동변환 — 제목(연도·회차)을 알아서 읽음

쪽 안에 «2025년 제1회» 가 안 적힌 PDF 가 흔하다.
그동안은 사람이 **연도·회차 칸을 채워야** 했고, 안 채우면 **문항 0개**로 끝났다.

이제 파일마다 **세 걸음**으로 알아서 정한다.

| 순서 | 무엇을 보나 | 기록에 찍히는 말 |
|---|---|---|
| ① | 위 «연도·회차» 칸을 사람이 채웠나 | `회차 직접 지정 — 2025년 제3회` |
| ② | 앞 8쪽 안에 «○○○○년 제○회» 가 있나 | `회차 표시가 쪽 안에 있습니다 — 쪽마다 읽습니다` |
| ③ | **파일 이름**에 적혀 있나 | `파일 이름에서 읽었습니다 — 2025년 제3회` |

셋 다 없으면 이렇게 알려 준다 — 예전처럼 조용히 0개로 끝나지 않는다.

> ⚠ 쪽에도 파일 이름에도 회차가 없습니다 — 위 «연도·회차» 칸을 채우거나
> 파일 이름을 «2025년 3회.pdf» 처럼 바꿔 주세요

### 읽는 이름 모양

```
2025년 3회.pdf            → 2025년 3회
전기기사 실기 2024-2.pdf   → 2024년 2회
25년1회 기출.pdf          → 2025년 1회
2023_3회_실기.pdf         → 2023년 3회
2026.1 실기.pdf           → 2026년 1회
2022 제2회 전기기사.pdf    → 2022년 2회
```

엉뚱한 것에 안 걸리는지도 확인했다.

```
ALL_OCR.pdf              → 못 찾음 (맞음)
다산 기출문제집 전권.pdf    → 못 찾음 (맞음 — 한 권짜리는 쪽 안에서 읽어야 함)
전기기사 2024 문제 3권.pdf → 못 찾음 (맞음 — «3권» 을 3회로 읽지 않음)
```

**②가 ③보다 먼저인 이유** — 한 권짜리 PDF 는 쪽마다 회차가 바뀐다.
파일 이름 하나로 씌워 버리면 1204쪽이 전부 같은 회차가 되어 버린다.
쪽 안에 표시가 있으면 이름표를 억지로 씌우지 않는다.

## 7. 중복 찾기 · 합치기

오고초려·핵심빈출은 **기출에서 골라 모은 것**이라 원본이 따로 있다.
같은 문제가 두 군데 앉아 있으면 격자에서 두 번 세어지고,
**한쪽에만 해설이 붙는** 일도 생긴다.

검수 화면에 **「중복 찾기 · 합치기」** 칸을 넣었다.

### 짝을 찾는 잣대

**문제 본문 글자.** 띄어쓰기·문장부호·`[[그림]]` 자리표를 걷어내고 앞 120글자를 견준다.
그래서 이런 것도 같은 문제로 잡는다.

```
2019-2 5번 : 그림과 같은 3상 4선식 배전선로에 역률 100[%] 인 부하 a-n, b-n, …
9301-1 3번 : 그림과 같은  3상 4선식 배전선로에 역률 100 % 인 부하 a-n , b-n , …
             → 같은 문제
```

그림만 있고 글이 없는 문항은 **견줄 것이 없어 건너뛴다.** 몇 개를 건너뛰었는지 같이 알려 준다.

### 원본을 고르는 규칙

**실제 기출 회차를 먼저, 그중 이른 해를.**
오고초려·핵심빈출·단답은 사본이 된다 — 그게 원래 어디서 왔는지가 중요하기 때문이다.

### 합칠 때 하는 일

| | |
|---|---|
| ① | 사본에만 있는 **답·해설을 원본으로 옮긴다** — 이게 진짜 값어치다 |
| ② | 사본에 «어느 문항의 사본인지» 표시를 단다 (`dup_of`) |
| ③ | **사본을 지우지는 않는다** — 잘못 골랐으면 되돌릴 수 있어야 하므로 |

**「표시 지우기」** 로 언제든 원상복구된다. 옮겨 간 답·해설은 그대로 남는다.

### 표시된 뒤에는

- 격자에서 **흐리게 «사본»** 으로 뜬다
- **빈칸 세기·통계·텍스트 뽑기에서 빠진다** — 사본이 비어 있는 건 할 일이 아니다.
  원본을 채우면 되는 것이므로
- 「전 회차 빈칸 모아보기」에도 안 나온다

> 시험 삼아 돌려 본 결과 —
> `무리 1 · 원본 2019-2 5번 ← 사본 9301-1 3번, 9302-2 7번 · 옮길 칸: 답·해설`

**SQL 을 한 번 더 돌려야 한다** — `supabase-review.sql` 아래쪽 **«추가분 (v216)»**.
`dup_of` 칸 하나를 더한다. 안 돌리면 «dup_of 칸이 아직 없습니다» 라고 알려 준다.

   검수 화면에서 **「중복 찾기」** 한 번 — 몇 무리가 잡히는지 (7번).
   숫자만 보고 «합치기 실행» 은 나중에 눌러도 된다

## 덧붙임 — 파일 이름 깨짐 고침

압축을 풀면 `supabase-검수.sql` · `변경내역-v216.md` 이름이 깨져 나왔음.
리눅스 `zip` 이 한글 이름을 UTF-8 로 담으면서 «이건 UTF-8 이다» 표시(0x800)를
안 붙여서, 윈도우 탐색기가 CP949 로 잘못 읽은 것임.

두 가지를 같이 했음.

1. 압축을 파이썬 `zipfile` 로 다시 떴음 — 한글 이름에 UTF-8 표시를 자동으로 붙임
2. 그래도 안전하게, 한글 이름 두 개를 영문으로 바꿨음

| 예전 | 지금 |
|---|---|
| `supabase-검수.sql` | `supabase-review.sql` |
| `변경내역-v216.md` | `CHANGELOG-v216.md` |

`review.html` 안에서 «supabase-검수.sql 을 먼저 돌려 주세요» 라고 안내하던
문구 세 곳도 새 이름으로 같이 고쳤음. **내용은 하나도 안 바뀜 — 이름만 바뀐 것.**
이미 SQL 을 돌렸다면 다시 돌릴 필요 없음.
