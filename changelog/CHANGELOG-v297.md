# v297 — 해설 «원칙 검사»: 형식 못 지킨 해설은 다시 받고, 그래도 안 되면 덮지 않음

고친 파일: `practice.html` · `gichul-ai-worker/src/index.js`(워커 — 재배포, 빌드 v297) · `sw.js` · `index.html`

## 원인
- 25-2 19 처럼 계산 문제인데 «먼저 알아야 할 것 · 주어진 값 한 줄 · 답» 만 저장된 것:
  모델이 풀이 단계(식 네 줄)·부호·검산을 비운 채 답했는데,
  워커는 «steps 가 아예 없나» 만 보고 한 번 더 받은 뒤 결과가 같아도 그대로 돌려줬고, 화면은 그대로 저장했음

## 워커 — 유형마다 반드시 있어야 할 칸을 검사 · 빠진 곳을 짚어 최대 두 번 더
- 모든 유형: 풀이 단계(소문항 수만큼 · (1)~(n) 모두) · 답 · 단계마다 «왜»
- 계산 · 표·선정: 주어진 값(숫자·조건 전부, 2개 이상) · 부호 · 먼저 알아야 할 것 · 검산
  · 식 네 줄(부호식·해설식·숫자대입식·단위식)을 다 갖춘 단계 · 숫자를 넣은 단계는 네 줄 모두
- 단답·서술·나열: 단계마다 그 소문항 답
- 도구 틀에서 background · given · symbols 를 필수 칸으로 (유형에 안 맞으면 빈 배열)
- 세 번 받은 것 중 어긴 곳이 가장 적은 것을 쓰고, 남은 문제를 problems 로 돌려줌

## 화면
- 원칙 미달로 오면: 있던 해설이 있으면 «바꿀까요?» 로 물음 (취소 = 그대로) · 없던 문항이면 저장하고 ⚠ 알림
- 여러 문항 돌리기: 있던 해설은 그대로 두고 «실패» 로 셈 → 다시 돌리면 됨
- 워커가 옛 판이어도 화면이 같은 검사를 한 번 더 함

## 디버그 후 보탬 (같은 v297)
- 시간: 워커가 최대 세 번 받으면 Opus 로 5분을 넘길 수 있어 화면이 끊고 «실패» 했음
  → 화면(실기·검수) 기다림 5분 → 10분 · 워커는 시작 3분 30초가 지나면 더 받지 않음
- 표·선정: «표에서 바로 위 값 고르기» 단계(식 없음이 정상)를 미달로 잡던 것 → 네 줄 빈칸 검사는 계산형만
- 검수(review.html) · 해설 배치(explain-batch.html)도 원칙 미달이면 있던 해설을 덮지 않음 (배치 기록에 ⚠)
- 한 문항 뽑기가 실패하거나 «그대로 둠» 을 고르면, 카드에 «쓰지 못했습니다» 만 남아 있던 해설이 안 보이던 것 → 원래 해설로 되돌림
- 확인: 가짜 응답(불량→불량→정상)으로 워커 전체를 돌려 세 번째 것을 고르는 것 · 셋 다 불량이면 problems 로 돌려주는 것
